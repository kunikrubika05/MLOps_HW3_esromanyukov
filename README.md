# Переобучение модели в Airflow

Kafka → скоринг CatBoost → PostgreSQL со скором, флагом фрода и версией модели. Airflow обновляет данные, переобучает модель и проверяет витрину

Склонируйте репозиторий и перейдите в его каталог. Нужны Docker Compose и 4 ГБ памяти для Docker. Положите `train.csv` из HW1 в `data/`

```bash
docker compose up -d --build --wait
```

[Airflow](http://localhost:8081): `admin` / `admin`. [Скоринг](http://localhost:8501)

В Airflow откройте DAG и нажмите **Trigger DAG**: `supply_labeled_batch` добавляет месяц, `retrain_catboost` переобучает модель, `data_quality` проверяет данные. Дождитесь статуса **success**. `data_quality` запускайте после успешного `retrain_catboost`

Расписание — раз в 5 минут, `catchup=False`. Батч — до 100000 строк, история — 36 месяцев. Скользящее окно — 3 месяца: первые 2 для обучения, последний для проверки. Препроцессинг из HW1 рассчитывается только по обучающей части

Новую и текущую модели сравниваем на одном проверочном месяце по PR-AUC (`average_precision_score`) и ROC-AUC. Публикуем новую, если обе метрики не ниже прежних; при одном классе в проверочной части публикации нет. Решения сохраняются в `runtime/candidates/`

После выполнения `retrain_catboost` отправьте транзакции

```bash
docker compose run --rm tools python produce.py --csv /data/demo.csv --limit 6
```

Через несколько секунд проверьте активную версию и результаты

```bash
cat runtime/models/latest.txt
docker compose exec postgres psql -U fraud -d fraud -c 'select score, fraud_flag, model_version from scores order by id desc limit 6;'
```

`model_version` должна совпасть с `latest.txt`. Новая модель подхватывается без перезапуска скоринга; при отклонении кандидата активная версия сохраняется

DQ-проверки:

1. Контракт витрины: нужные столбцы, типы и заполненные обязательные поля
2. Допустимые значения: конечные неотрицательные суммы, целое неотрицательное население и координаты в допустимых пределах
3. Целостность месяцев: время соответствует месяцу строки, нет пропущенных месяцев
4. Корректная разметка: метки только 0 или 1
5. Целостность загрузки: ключи уникальны, число строк добавленного месяца совпадает с размером батча
6. Разбиение по времени: обучающие данные строго раньше проверочных, ключи строк частей не пересекаются

Разбиение проверяется по файлам последнего завершённого переобучения; до их появления проверка ожидает данные. Наличие обоих классов выводится отдельно как готовность к обучению и расчёту метрик

HTML-отчёты — в `runtime/reports/`, рядом с моделями в `runtime/models/`. При нарушениях отчёт сохраняется, а таска завершается ошибкой

Остановка

```bash
docker compose stop
```
